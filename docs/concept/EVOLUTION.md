# Auto‑bench с эволюцией каталога

Ключевая фича проекта. Тезис: знание о маршрутизации живёт в человекочитаемом каталоге, а не в весах модели, поэтому ошибку роутера можно исправить правкой каталога за минуту, с регрессионным тестом и человеком в контуре. У энкодерного классификатора тот же цикл это разметка, переобучение и релиз.

## 1. Цикл

```text
 ошибка в трассировке ──► кейс (реплика + контекст + ожидание) ──► патч каталога (gpt-6-sol)
        ▲                                                                   │
        │                                                                   ▼
 hot reload ◄── версия каталога ◄── одобрение супервизора ◄── регрессия до/после (dev + кейсы)
```

Каждая ошибка навсегда становится тестом. Каждая правка каталога проходит регрессию до применения. Каждая версия каталога имеет хэш и откат.

## 2. Объекты

Схемы в [/contracts/evolution.schema.json](../../contracts/evolution.schema.json), примеры в [/fixtures/supervisor](../../fixtures/supervisor).

**Case** — тест‑кейс маршрутизации.

```json
{
  "case_id": "CASE-0001",
  "source": "supervisor",
  "text": "Выплату одобрили, но сумма какая-то маленькая, я не согласен",
  "lang": "ru",
  "context": {"active_scenario": null, "client": {"client_id": "C005"}},
  "expected": ["SC19"],
  "observed": ["SC17"],
  "session_id": "web-7f3a",
  "turn": 2,
  "created_at": "2026-10-01T12:03:11Z"
}
```

`source`: `supervisor` (пометка в панели), `synthetic` (прогон синтетических клиентов), `dev` (dev_utterances, только для чтения).

**BenchRun** — прогон роутера на наборе.

```json
{
  "run_id": "BR-0007",
  "catalog_version": "v3-9f2c",
  "dataset": {"dev": 104, "cases": 6},
  "status": "finished",
  "started_at": "2026-10-01T12:04:00Z",
  "finished_at": "2026-10-01T12:04:17Z",
  "metrics": {
    "all": {"n": 110, "primary_acc": 0.936, "full_match": 0.909},
    "by_lang": {"ru": {"n": 70, "primary_acc": 0.957, "full_match": 0.929}, "kk": {"n": 30, "primary_acc": 0.9, "full_match": 0.867}, "mixed": {"n": 10, "primary_acc": 0.9, "full_match": 0.9}},
    "by_type": {"single": {"n": 88, "primary_acc": 0.955, "full_match": 0.955}, "multi_intent": {"n": 15, "primary_acc": 0.867, "full_match": 0.733}, "out_of_scope": {"n": 4, "primary_acc": 1.0, "full_match": 1.0}, "unclear": {"n": 3, "primary_acc": 0.667, "full_match": 0.667}},
    "intent_recall": 0.9
  },
  "latency_ms": {"router_p50": 640, "router_p95": 1180},
  "errors": [{"id": "CASE-0001", "text": "...", "expected": ["SC19"], "got": ["SC17"]}]
}
```

**Patch** — предложение правки каталога с результатом регрессии.

```json
{
  "patch_id": "PT-0003",
  "status": "ready",
  "case_ids": ["CASE-0001"],
  "base_version": "v3-9f2c",
  "proposal": {
    "ops": [
      {"op": "add", "scenario_id": "SC17", "field": "not_this_if", "value": {"condition": "Client disagrees with the approved amount or the decision", "use_instead": "SC19"}},
      {"op": "append", "scenario_id": "SC19", "field": "examples.ru", "value": "Одобрили, но сумма меньше, чем насчитали в сервисе"}
    ],
    "rationale": "Disagreement with an approved amount was routed as a status request; the boundary rule was missing on SC17."
  },
  "regression": {
    "before": {"run_id": "BR-0007", "primary_acc": 0.936, "full_match": 0.909},
    "after": {"run_id": "BR-0008", "primary_acc": 0.945, "full_match": 0.918},
    "fixed": ["CASE-0001"],
    "broken": []
  },
  "created_at": "2026-10-01T12:04:20Z"
}
```

**CatalogVersion** — снапшот каталога.

```json
{"version": "v4-1a7e", "parent": "v3-9f2c", "hash": "1a7e...", "applied_patch": "PT-0003", "created_at": "2026-10-01T12:05:02Z", "frozen": false, "note": "SC17/SC19 boundary"}
```

## 3. Потоки

**Пометка ошибки.** В трассировке хода кнопка «неверно» → выбор правильных сценариев (мультивыбор, порядок важен) → `POST /api/cases`. Кейс появляется в очереди «спорные ходы».

**Предложение патча.** `POST /api/patches` с `case_ids` → фоновая задача. Патчер получает: текст кейса и контекст, определение неверного и правильного сценариев полностью, `reason` и `boundary_rule` роутера, до 3 похожих кейсов. Возвращает `ops` по строгой схеме. Прогресс и готовность приходят событиями `patch.progress` и `patch.ready` в supervisor WS.

**Регрессия.** Раннер собирает каталог `base_version + ops` во временную версию, гонит dev‑набор и все кейсы в 20 потоков через тот же роутер, что работает в диалоге, и сравнивает с последним прогоном базовой версии. Метрики те же, что в evaluate.py, плюс `fixed` и `broken` по идентификаторам. 110 реплик укладываются в 15–20 секунд, стоимость меньше цента благодаря кэшу префикса.

**Применение.** `POST /api/patches/{id}/apply` → новая версия каталога, запись в `/catalog/vN-hash.json`, горячая перезагрузка промпта роутера, прогрев кэша одним запросом с `max_output_tokens: 1`. Событие `catalog.changed` уходит всем панелям. `POST /api/catalog/rollback` возвращает любую предыдущую версию тем же путём.

**Заморозка.** `POST /api/catalog/freeze` ставит `frozen = true`: применение патчей запрещено, панель показывает замок и хэш. Включаем на время зачётного прогона и говорим об этом жюри.

## 4. Патчер

Модель `gpt-6-sol`, `effort: "medium"`, structured outputs. Ограничения зашиты в схему и в валидатор:

- Разрешённые операции: `add` в `not_this_if`, `replace` для `description`, `append` в `examples.ru` / `examples.kk`, `remove` конкретного примера или правила. Идентификаторы, слоты, действия, приоритеты и флаги не трогаются, так оценка по исходным 40 сценариям остаётся валидной.
- Не больше 4 операций на патч, не больше 2 сценариев.
- Правило `not_this_if` обязано ссылаться на существующий `use_instead`.
- **Защита от хардкода.** Пример, добавляемый в `examples`, не может совпадать с текстом кейса: нормализованное сходство по `difflib.SequenceMatcher` выше 0.85 отклоняется валидатором, патчер получает отказ и перегенерирует с требованием обобщить формулировку. Это снимает подозрение, что мы подкладываем проверочные фразы жюри.
- Патчер обязан предпочесть правило границы добавлению примера: сначала `not_this_if`, примеры только если граница уже описана.

Каркас промпта патчера:

```text
You maintain the scenario catalog of an insurance voice assistant. A router based on this catalog
misrouted a client utterance. Propose the smallest catalog change that fixes the routing without
breaking neighbouring scenarios. Prefer boundary rules (not_this_if) over new examples. Never copy
the utterance verbatim into examples; generalize. Explain the root cause in one sentence.
Wrong scenario: {...}  Correct scenario: {...}  Utterance: "..."  Router reason: "..."
Similar past cases: [...]
```

## 5. Регрессионный раннер

- Вход: версия каталога (или временная), набор = `dev_utterances.json` + `regression/cases.jsonl`.
- Один и тот же код роутера, что в диалоге, чтобы bench мерил именно то, что слышит жюри. Контекст кейса подставляется в `state`, у dev‑реплик состояние пустое.
- Параллелизм 20, таймаут 8 с на реплику, одна повторная попытка.
- Детерминизм: `temperature: 0` там, где модель это принимает; итог считаем по одному прогону, при спорной дельте меньше 1 п.п. запускаем второй и усредняем.
- Отчёт пишется в `regression/runs/BR-xxxx.json` и в SQLite, панель показывает тренд по версиям каталога.
- `make bench` запускает тот же раннер на текущей версии и печатает вывод, идентичный `python docs/evaluate.py`.

## 6. Интерфейс супервизора

1. Очередь спорных ходов: уверенность ниже порога, `SYS_UNCLEAR`, переводы, ручные пометки. У каждого хода реплика, что выбрано, что предлагалось, обоснование.
2. Кнопка «неверно» → выбор правильных сценариев → кейс создан, кнопка «предложить патч».
3. Карточка патча: дифф каталога (до/после по полям), объяснение причины, таблица метрик до/после, списки починенных и сломанных, кнопки «применить» и «отклонить».
4. История версий каталога с хэшами, тренд `primary_acc` и `full_match`, откат.
5. Индикатор заморозки и текущий хэш всегда видны в шапке.

События и REST описаны в [/contracts/openapi.yaml](../../contracts/openapi.yaml) и [/contracts/ws-events.schema.json](../../contracts/ws-events.schema.json).

## 7. Честность

- На зачётном прогоне каталог заморожен, хэш версии на экране, все ходы логируются с этим хэшем.
- Патчер не добавляет дословные фразы, валидатор это проверяет и пишет отказ в лог.
- Dev‑набор используется только как тест, в промпт роутера не попадает.
- В README прямо пишем границу применимости: цикл улучшает разграничение существующих сценариев, он не заменяет проектирование новых продуктов и не отменяет контроль человека.

## 8. Расширения

- **Синтетические клиенты.** `gpt-6-sol` играет персоны из mock_backend.json: смена темы, kk/ru вперемешку, невнятные запросы, раздражение. Прогон 30 диалогов в текстовом режиме заполняет матрицу ошибок и создаёт кейсы `source = synthetic`.
- **Рост каталога.** Кластер частых `SYS_UNCLEAR` и `SYS_OUT_OF_SCOPE` реплик → черновик нового сценария (описание, границы, примеры) на утверждение. Роутинг по нему включается только после ревью.
- **Автоподбор порогов.** Bench считает точность по корзинам уверенности и предлагает пороги 0.75/0.45 пересчитать; применение тоже через одобрение.

## 9. Демо за 60 секунд

1. Панель: каталог `v3-9f2c`, заморожен. Зачёт прошёл, снимаем заморозку.
2. Фраза «Выплату одобрили, но сумма маленькая, я не согласен» ушла в SC17. Клик «неверно» → SC19.
3. «Предложить патч». Через 15–20 секунд дифф: новое правило границы у SC17, обобщённый пример у SC19, причина одной строкой. Таблица: primary_acc 0.936 → 0.945, сломанных нет.
4. «Применить». Хэш в шапке сменился на `v4-1a7e`.
5. Повторяем фразу вслух: SC19, уверенность 0.9, ответ с эмпатией и предложением оформить несогласие.

## 10. Объём работ

| Часть | Оценка | Зависимости |
|---|---|---|
| Регрессионный раннер и хранилище прогонов | 1–2 ч | роутер |
| Патчер: промпт, схема, валидатор, сборка временной версии | 2–3 ч | раннер |
| Версии каталога, hot reload, прогрев кэша, заморозка, откат | 1–2 ч | роутер |
| REST + события supervisor WS | 1 ч | |
| Фронт: очередь, кнопка «неверно», карточка патча, история версий | 3–4 ч | fixtures |

Раннер нужен в любом случае для калибровки порогов, поэтому чистая стоимость фичи это патчер, версии и фронт, около одного человеко‑дня.
