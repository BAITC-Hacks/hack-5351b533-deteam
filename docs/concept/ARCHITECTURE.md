# Voice Router — концепт и архитектура

Кейс 2 HackAlem (трек Halyk Bank), страховая Saqta Insurance. Документ для команды: что строим, из чего, как это соединяется и что показываем жюри. Контракты для смежников лежат отдельно: [frontend](../frontend/README.md), [telephony](../telephony/README.md), схемы в [/contracts](../../contracts), шаблонные данные в [/fixtures](../../fixtures).

Ограничение команды: все AI‑модели только OpenAI. VAD (Silero) это не языковая модель, а детектор речи, он допустим; при желании заменяется на энергетический VAD без внешних моделей.

Дата среза данных кейса: `2026-10-01`, считаем её «сегодня» во всём, что касается дат в диалоге.

---

## 1. Что оценивают и во что мы целимся

| Критерий | Баллы | Чем берём |
|---|---|---|
| Соответствие задаче и работоспособность | 25 | Голос в вебе, 40 сценариев, идентификация по телефону, подтверждения, перевод на оператора |
| Техническая реализация | 25 | LLM‑роутер со структурным выводом, спекулятивная маршрутизация, исполнитель‑автомат, эволюция каталога с регрессией |
| README и воспроизводимость | 25 | `docker compose up`, evaluate.py из коробки, документы этой папки |
| Ценность и применимость | 15 | Телефонный канал через Asterisk, супервизор правит маршрутизацию без разработчиков |
| Потенциал и оригинальность | 10 | Auto‑bench с эволюцией: каждая ошибка становится тестом и патчем |

Живой прогон: жюри зачитывает 10 скрытых реплик, до 3 баллов за каждую (основной сценарий, все сценарии при мульти‑интенте либо язык ответа, качество ответа по данным). Задержка от конца речи до начала ответа даёт бонус: медиана ≤ 1.5 с это +2, ≤ 3 с это +1.

Наш тезис одной фразой: слой решения это LLM над человекочитаемым каталогом сценариев, поэтому он понимает живую речь и исправляется правкой каталога за минуту, а не переобучением.

## 2. Состав системы

```text
 Каналы            Web (браузер, WebSocket)   Телефон (Asterisk → AudioSocket)   Текст (text.input / REST)
                            │                            │                              │
 Транспорт          PCM16 16 kHz ◄──────────── PCM16 8 kHz → ресемпл 16 kHz             │
                            └────────────────────┬───────┘                              │
 VAD (Silero) ── speech_start / speech_end (t0)  │                                      │
 STT  OpenAI gpt-live-transcribe (Realtime transcription WS, партиалы + финал)          │
                            │ partial ───────► спекулятивный роутинг                    │
                            │ final ──────────────────────────────────────────────────►─┘
 Роутер  gpt-6-luna, effort none, structured outputs, кэш каталога   ◄── Состояние диалога
                            │ language, scenarios[], confidence, slots, is_continuation
 Политика решения  ≥0.75 run | 0.45–0.75 clarify (+ второе мнение gpt-6-sol) | <0.45 ×2 handoff
                            │
 Исполнитель сценариев  идентификация → слоты по одному → действия → подтверждение → закрытие
                            │                    моки: mock_backend.json + knowledge_base.json
 Ответ   шаблоны (0 мс)  |  gpt-6-luna streaming для ответов по базе знаний
                            │
 TTS  gpt-4o-mini-tts, pcm 24 kHz, стриминг, кэш предсинтезированных фраз
                            │
 Трассировка  turn.trace + latency_ms → панель фронта, supervisor WS, SQLite
                            │
 Auto‑bench + эволюция  кейсы → патч (gpt-6-sol) → регрессия → версия каталога → hot reload
```

## 3. Стек

| Слой | Выбор | Параметры | Почему |
|---|---|---|---|
| Роутер | `gpt-6-luna` | Responses API, `reasoning.effort: "none"`, structured outputs strict, prompt caching, `max_output_tokens` ~250, stream | Самая быстрая и дешёвая в линейке, 1M контекст, кэш‑чтение $0.01/M. Один вызов: язык, сегменты, сценарии, слоты |
| Второе мнение | `gpt-6-sol` | `effort: "low"` | Только для зоны 0.45–0.75. Точность важнее задержки, таких реплик мало |
| Запасной роутер | `gpt-5.6-luna` | те же параметры | Переключение через env, если у 6 Luna лимиты или сбои |
| Генерация ответа | `gpt-6-luna` | `effort: "none"`, stream, 1–2 предложения | Только для ответов по базе знаний и эмпатии. Остальное шаблоны |
| Патчер каталога | `gpt-6-sol` | `effort: "medium"`, structured outputs | Предлагает минимальные правки каталога, см. [EVOLUTION.md](EVOLUTION.md) |
| Синтетический клиент | `gpt-6-sol` | персоны из mock_backend | Стресс‑прогоны и пополнение кейсов |
| STT | `gpt-live-transcribe` | Realtime transcription session, `languages: ["ru","kk"]`, `delay: "low"`, `keywords`, `prompt` | Дельты по мере речи нужны для спекулятивного роутинга. Серверного VAD у модели нет, VAD свой |
| VAD | Silero VAD | порог тишины 250–300 мс | Момент конца речи это t0 замера, его контролируем сами |
| TTS | `gpt-4o-mini-tts` | `response_format: "pcm"` (24 kHz), стриминг, `instructions` под язык и тон | Казахский в списке языков. Голос выбираем ушами в первый час |
| Числа словами | `num2words` | `lang="ru"`, `lang="kz"` | «тридцать восемь тысяч тенге» по правилам кейса |
| Бэкенд | Python 3.12, FastAPI, asyncio, SQLite | | Один процесс: транспорт, пайплайн, REST, supervisor WS |
| Фронтенд | React + Vite + TypeScript, AudioWorklet | | Контракт в [docs/frontend](../frontend/README.md) |
| Телефония | Asterisk 20/22, AudioSocket, func_curl, AMI | | Контракт в [docs/telephony](../telephony/README.md) |
| Инфра | docker compose | `docker compose up` | Требование «запуск одной командой» |

Почему не speech‑to‑speech (`gpt-realtime-2.1`, `gpt-live-1`): выбор сценария там происходит внутри модели, отдельного этапа для трассировки нет, evaluate.py всё равно требует текстовый роутер, а GPT‑Live перефразирует наш текст вместо дословного произнесения (номера полисов, маски email, точные суммы). Оставляем как возможный режим шоу, не как основу.

Транспортный слой пишем сами (WebSocket для веба, AudioSocket для телефона): Pipecat не имеет AudioSocket‑транспорта, а два кастомных транспорта проще собрать на asyncio, чем встраивать во фреймворк. Ядро пайплайна около 500 строк.

## 4. Один ход диалога и бюджет задержки

Точка отсчёта t0 это `vad.speech_end` на сервере. Все поля `latency_ms` считаются от событий сервера, клиент дополнительно присылает `playback.started` для сверки с секундомером жюри.

| Поле `latency_ms` | Определение | Наивно | Цель |
|---|---|---|---|
| `stt` | финальный транскрипт − t0 | 200–300 | 150–250 |
| `triage` | нормализация + fast path − stt | 5–20 | 5–20 |
| `router` | результат роутера − triage | 700–1000 | 0–150 при спекулятивном попадании |
| `response` | первое предложение ответа готово − router | 400–600 | 0 для шаблонов, ~400 для KB |
| `tts_first_audio` | первый аудио‑чанк отправлен − response | 250–400 | 0 из кэша, ~250 стрим |
| `total` | первый аудио‑чанк отправлен − t0 | ~2000 | 900–1300 медиана |

Пять приёмов, которые дают разницу:

1. **Спекулятивный роутинг.** На каждый стабилизировавшийся партиал транскрипта запускаем роутер. По `speech_end` финальный текст чаще всего совпадает с последним отправленным, ответ уже лежит. Иначе один финальный вызов. В трассировке поле `speculative_hit`.
2. **Порядок полей в JSON.** `language`, `is_continuation`, `scenarios` идут первыми, `reason` коротким, `slots` и `alternatives` в конце. Исполнитель стартует по первому распарсенному `scenario_id` из стрима.
3. **Шаблоны вместо генерации.** Вопросы по слотам (slots.json), открывающие и закрывающие фразы (scenarios.json), SYS_* ответы. Это около половины реплик.
4. **Предсинтез аудио.** Все шаблонные фразы прогоняем через TTS при старте контейнера, PCM лежит в кэше по ключу (text, lang, voice). Для них `tts_first_audio = 0`.
5. **Стабильный префикс промпта.** Каталог в system как неизменяемый блок, динамика (состояние, реплика) в конце. Кэш прогреваем при старте и после каждой смены версии каталога.

Дополнительно: соединения к OpenAI держим тёплыми (HTTP/2 пул, WS транскрипции открыт на всю сессию), RTT из Казахстана до OpenAI добавляет 150–250 мс на каждый вызов.

## 5. Роутер, кратко

Подробно в [ROUTER.md](ROUTER.md). Один вызов LLM делает всё, что в референсной архитектуре разнесено на триаж и роутер: определяет язык (`ru`/`kk`/`mixed`), режет реплику на сегменты при нескольких намерениях, выбирает сценарии с уверенностью, извлекает и нормализует слоты, распознаёт продолжение активного сценария и ответ «да/нет» на подтверждение.

| Уверенность | Решение |
|---|---|
| ≥ 0.75 | запустить сценарий |
| 0.45–0.75 | второе мнение `gpt-6-sol`; если тоже неуверенно, `SYS_UNCLEAR` с двумя вариантами |
| < 0.45 два раза подряд или просьба клиента | перевод на оператора с контекстом |
| несколько сценариев | сначала `urgent`, затем в порядке упоминания, проговорить, что остальное тоже сделаем |
| продолжение активного сценария | заполнить слоты, роутинг не перезапускать |

Пороги перекалибруем на dev‑наборе. Детерминированные продолжения без LLM разрешены и не являются классификатором: ожидаемый слот совпал с regex (телефон, ИИН, госномер, дата), «да/нет» на preview, явное «оператор», прощание после закрытия сценария.

## 6. Исполнитель сценариев

Один универсальный автомат, параметризованный записью из scenarios.json.

```text
 start ─► [requires_identification?] ─► identify (phone|iin|policy|claim)
       ─► collect_slots (по одному, шаблонный вопрос из slots.json, валидация по pattern, повтор один раз)
       ─► run_actions (моки; ошибки по actions.json.error_handling)
       ─► [requires_confirmation?] ─► preview (озвучить данные) ─► ждать явное «да» ─► execute
       ─► closing (шаблон или KB‑ответ) ─► [handoff.when?] ─► transfer_to_operator с резюме
```

- **Идентификация по номеру звонящего.** На телефоне caller ID приходит от Asterisk, в вебе поле «звоню с номера» в интерфейсе. `find_client` вызывается при старте сессии, слот `phone` тогда не спрашиваем. Это прямо закрывает требование «персоны из mock_backend, идентифицировать по телефону».
- **Стек тем.** Смена темы кладёт активный сценарий в стек с заполненными слотами, после завершения нового предлагаем вернуться. Возврат к стеку виден в `dialog.state`.
- **Заземление фактов.** Карта «сценарий → разделы knowledge_base.json» (SC33 → offices, SC31 → payments, SC23 → clinics и т. д.). Генератор ответа получает только эти разделы и результаты действий.
- **Необратимые действия.** `create_policy`, `renew_policy`, `update_policy`, `cancel_policy`, `create_claim`, `create_dispute`, `book_inspection`, `book_appointment`, `update_contact` идут только через preview → явное «да» → execute. В трассировке действие показывается как `name:preview`, затем `name`.
- **Ошибки моков.** Единый формат `{"error": {"code", "message"}}`, поведение по `error_handling`: `not_found`/`invalid_input` переспросить один раз, затем другой идентификатор или оператор; `service_unavailable` повторить один раз, затем перевод.
- **Новые идентификаторы** моков не пересекаются с существующими: счётчики от максимального номера в mock_backend.json.

## 7. Ответ и голос

- **Язык ответа.** Преобладающий язык реплики; при `mixed` язык ядра запроса; явная просьба «давайте на русском» переключает и запоминается в состоянии. Язык фиксируется в `bot.text.final.lang` и в трассировке.
- **Стиль.** 1–2 коротких предложения, один вопрос за раз, сначала понимание, потом действие, эмпатия в претензиях и жалобах, спокойствие и темп в срочных. Числа словами через num2words. PII при повторном озвучивании маскируется (`r***@mail.example`). На «вы робот?» отвечаем честно.
- **Шаблоны.** Вопросы по слотам, opening/closing сценариев, SYS_*, фразы подтверждения. Плейсхолдеры заполняются из слотов и результатов действий, суммы прогоняются через num2words до TTS.
- **Стриминг TTS.** Текст режем по предложениям, каждое уходит в TTS отдельным запросом, аудио стримится в канал. Для телефона ресемпл 24 → 8 kHz.
- **Перебивание.** VAD ловит речь во время воспроизведения: TTS останавливаем, отправляем `tts.interrupt`, клиент сбрасывает буфер, ход помечается `interrupted`.
- **Голос TTS.** Один многоязычный голос для ru и kk, `instructions` вида «Speak natural Kazakh, calm contact‑center operator, medium pace». Если казахский звучит плохо, это риск номер один, см. раздел 13.

## 8. Трассировка и панель

После каждой реплики клиента сервер отправляет `turn.trace` в формате README кейса плюс наши поля (`decision`, `speculative_hit`, `fast_path`, `catalog_version`, `router_model`, `response_text`). Полная схема в [/contracts/trace.schema.json](../../contracts/trace.schema.json). Все события сессии дублируются в supervisor WS и пишутся в SQLite.

Панель супервизора считает: распределение сценариев, гистограмму уверенности, p50/p95 задержек по этапам, доли `SYS_UNCLEAR` и переводов, разбивку по языкам, очередь спорных ходов (уверенность < 0.75 или ручная пометка).

## 9. Auto‑bench с эволюцией каталога

Ключевая фича, подробно в [EVOLUTION.md](EVOLUTION.md). Коротко: ошибка в трассировке одной кнопкой становится кейсом, `gpt-6-sol` предлагает минимальный патч каталога (только `description`, `not_this_if`, `examples`), регрессия на dev‑наборе и накопленных кейсах бежит параллельно за 15–20 секунд, супервизор видит дифф и таблицу до/после, применяет, каталог перезагружается на лету. Версии с хэшем, откат в один клик, режим заморозки на время зачётного прогона.

## 12. Демо для жюри

1. Открываем веб, вводим номер звонящего из mock_backend, жмём микрофон. На панели горит версия каталога и статус «заморожен».
2. Жюри читает 10 реплик. На каждой видно: партиалы транскрипта, живые гипотезы роутера во время речи, трассировка с обоснованием и альтернативами, водопад задержек.
3. Одна реплика с телефона через софтфон: тот же диалог, идентификация по caller ID без вопроса про номер.
4. После зачёта: берём промах или заготовленную пограничную фразу, кнопка «неверно», через 20 секунд дифф патча и таблица до/после, применяем, повторяем фразу вслух, ответ правильный. Фраза для сравнения: у энкодерного классификатора этот цикл занимает дни и ML‑команду.

## 13. Риски и проверки первого часа

| Риск | Проверка | Запасной ход |
|---|---|---|
| Казахский у `gpt-4o-mini-tts` звучит плохо | 10 фраз из scenarios.json на kk, слушаем | Подбор голоса и `instructions`; если не спасает, честно фиксируем в README как границу применимости |
| Казахский у `gpt-live-transcribe` распознаётся слабо | 10 фраз kk и 5 mixed, сравниваем с текстом | `delay: "medium"`, `keywords`, `prompt` с доменной лексикой |
| `gpt-6-luna` вышла 22 сентября, возможны лимиты | нагрузочный прогон bench 104 реплики | `ROUTER_FALLBACK_MODEL=gpt-5.6-luna` |

| Обвинение в хардкоде проверочных реплик | | заморозка каталога на зачёт, хэш на экране, патчер не добавляет дословные фразы |

| Роль | День 1 | День 2 |
